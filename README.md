# 校园网断网时继续上网（不拔网线）

## 问题原因

宿舍断网后**有线链路并没有断**——网线还插着，交换机和网关照样在，
只是校园网**停止认证**，出口被掐了。而 Windows 的默认设置是：

| 网卡 | 自动跃点 | 结果 |
|---|---|---|
| 以太网（有线） | 25（更低=优先） | 默认路由、DNS 全部走它 |
| WLAN（手机热点） | 50 | 排在后面，等于不用 |

所以插着网线时，即使手机热点已经连上、也能出网，Windows 仍然把默认路由和
DNS 查询交给那条**没有出口的有线**：数据包发进黑洞，DNS 要问 192.168.31.1 永远超时。
表现出来就是"连着热点却打不开网页，一拔网线就好了"。

> 附加因素：本机开着 Clash Verge 的 TUN 模式（虚拟网卡 `Meta`，跃点 0，接管全部公网流量），
> 它自己不产生出口，出站连接要"搭"在系统的物理默认路由上。物理层选错了网卡，
> 代理层同样一起没网。改跃点对两层同时生效。

## 学校官方断网规则

中国矿业大学信息化建设与管理处（nic.cumt.edu.cn）：

- **每周日至周四 23:30 停止上网认证，次日 7:00 恢复**网络正常接入；
- **每周五、周六夜间及节假日正常提供网络接入服务**。

## 现在的方案：两个定点任务（不常驻、不弹窗）

只在断网和恢复这两个时间点各跑一个**短任务**（几秒到几十分钟），判断依据仍是
**把探测包绑定到各网卡本机地址测真实出口**，不猜时间、不写死校历：

| 计划任务 | 触发 | 行为 |
|---|---|---|
| `NetSwitch-Night` | 每天 **23:30** | 每 60 秒探一次，**一旦确认有线真的断了**（校园网停认证）就把 `WLAN` 跃点设为 10、`以太网` 设为 90，然后**立刻退出**；到 23:50 还没断就什么都不做（周五周六、节假日不断网的日子正是靠这个自动跳过） |
| `NetSwitch-Morning` | 每天 **07:00** | 每 60 秒探一次，**一旦确认有线恢复上网**就把两块网卡恢复"自动跃点"（有线 25 优先，不耗手机流量），然后**立刻退出**；最晚等到 07:45 |
| `NetSwitch-Logon` | 每次登录 **+ 网络状态变化时** | 自动判断一次：插上网线且有线上网 → 5 秒后切回有线优先；校园网刚停认证 → 立刻切热点。事件触发（不轮询、进程平时不存在） |

三条任务都设成：**隐藏窗口**、**允许电池供电时运行**、**错过时间点会尽快补跑**
（笔记本 23:30 在睡眠中就等唤醒后立刻补做；醒来时若校园网已恢复，它会判定"不切"，什么也不改）。

一晚的开销就是两个进程、各活几秒（正常情况）。网线不用动；切换只改优先顺序，
**有线同网段（192.168.31.0/24）的内部资源照旧可访问**，也不用禁用/启用网卡。

覆盖不到的场景：**白天**校园网临时抽风（维护等）时，任务不会定期去探，但只要你插拔一次网线、或 WiFi 通断一次，就会触发判断并自动切；也可以直接双击
`切到手机热点.bat`。

### 时间线（一个断网的晚上）

| 时刻 | 发生的事 |
|---|---|
| 23:30 | 校园网停止认证 → 任务在一分钟内确认有线已断 → 把热点设为优先 → 退出 |
| 任意时刻 | 你打开手机热点（夜间没热点时任务也没法给你变出网来，但它已经把优先级摆好了） |
| 次日 7:00 | 校园网恢复 → 任务在一分钟内确认有线已通 → 恢复有线优先 → 退出 |
| 7:00 前 | 你还在睡、电脑也在睡：任务不会跑，醒来后补做一次即可 |

## 性能占用（本机实测）

| 项目 | 实测值 |
|---|---|
| 进程数 | **一晚 2 个**（断网 1 个 + 恢复 1 个），各活几秒~几十分钟，**没有任何常驻进程** |
| 窗口 | **无**（`-WindowStyle Hidden` + 任务本身标记为隐藏） |
| 单次运行 CPU | 约 0.7 秒（其中 ~0.55 秒是启动 PowerShell 的开销） |
| 触发方式 | 定时只在 23:30 / 07:00 两次；其余是登录和**网络状态变化**（插拔网线、校园网断/恢复、WiFi 通断）触发，一天通常几次，每次约 3 秒、隐藏窗口、**不轮询** |
| 内存 | 进程退出即释放，常驻 0 |
| 磁盘 | 每次运行追加几行日志（超 800 行自动截断） |
| 已废弃的旧方案 | ①每分钟起一个进程：CPU ~1072 秒/天 且**每分钟闪一个窗口**；②整夜常驻守护：无窗口但要守 8 小时 |

## 文件与用法

- `安装-夜间自动切换.bat` —— 装三个计划任务（会弹 UAC）；若当前正在夜间时段会立刻跑一次断网任务
- `查看状态.bat` —— 只读，列出每条线路的 IP、能不能出网、当前跃点，以及系统会把公网流量交给谁
- `切到手机热点.bat` / `切回有线优先.bat` —— 手动强制（会弹 UAC）
- `卸载-自动切换.bat` —— 删除全部任务、结束残留进程、恢复自动跃点，不留残余
- `net-switch.log` 有每次判定记录；时间点、跃点值等参数都在 ps1 顶部（`-NightTime` / `-MorningTime` / `-NightMinutes` / `-MorningMinutes`）
- 备选模式：`-Mode watch` 整夜常驻守护（不弹窗，但会常驻一个进程），一般用不上

## 方案 C：USB 网络共享（可选加固）

手机用数据线做 USB 网络共享，比 2.4 GHz 热点更稳、延迟更低，
会多出一块 `Remote NDIS` 网卡；脚本的自动识别已经把这类网卡算进"热点"一侧
（`RNDIS|Remote NDIS|USB.*Ethernet|iPhone|iOS|Android`），不用改配置。

## 注意事项

1. 早上 7:00 校园网恢复后，认证可能要求重新登录一次门户（`stu` 账号被踢过），
   登录后一切照旧。
2. 如果改了跃点后 Clash Verge 仍然"没网"，让它重新选一次出口：
   退出/重启 Clash Verge，或关掉再打开 TUN 模式（它的 `auto-detect-interface: true`
   会重新跟随系统默认接口）。
3. 本机 `Meta`(Clash TUN)、`Tailscale`、`VMware`、`Sangfor` 等虚拟网卡已被脚本排除，
   不参与选路。
4. 计划任务需要管理员权限；不用了随时用 `卸载-自动切换.bat` 撤销，不留残余设置。
